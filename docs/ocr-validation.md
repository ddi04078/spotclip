# OCR / 스크롤 개선 검증

이번 수정은 기존 데이터·지도 링크·Mock 체험을 유지하며 스크롤/가독성과 후보 추출에 한정합니다.

| 시나리오 | 확인 결과 |
|---|---|
| 높이 844px, 너비 320/390/1280px에서 휠로 마지막 결과 이동 | 통과, 실제 스크롤 위치 변경·마지막 버튼·하단 탭의 viewport 포함 검사 |
| 브라우저 body 높이가 콘텐츠 때문에 늘어남 | 수정 후 viewport 높이 이내임을 검사 |
| 후보 입력칸 가독성 | computed font-size 16px 이상 검사; 주소/안내 15px 적용 |
| 보고된 첫째/둘째 한영 중복, 셋째 깨진 상호 | 텍스트 재현 입력으로 1+1+1 후보 검사 |
| 붙은 도시명, 두 줄 주소 | 주소 유지 검사 |
| 서로 다른 주소의 같은 상호/지점 | 별도 후보 유지 검사 |
| 서로 다른 음식점과 영문 상호 목록 | 임의 한영 병합 금지 검사 |
| SNS 형태의 어두운 배경·흰 글씨 이미지 3장 | 실제 Tesseract로 3개 후보·주소 모두 검사 |
| 위 테스트의 첫째/둘째 상호 | 한글 상호 정확 일치 |
| 위 테스트의 셋째 상호 | 한글 인식은 여전히 불완전. 실제 읽힌 영문 `CAFE | GOT EVERYTHING`을 낮은 신뢰 후보로 표시하고 경고·사용자 수정 검사 |
| 사용자 확인 전 저장 | 저장소에 후보 자동 기록 없음 검사 |
| 확인 후 저장/새로고침/중복/지도 연결 | 기존 회귀 테스트 유지 |

SNS 형태 테스트 이미지는 제공된 3곳의 문구를 canvas로 그린 합성 이미지입니다.
사용자가 올린 원본 JPEG 파일을 직접 OCR 실행에 사용한 것은 아닙니다.
따라서 사용자 원본 사진에서의 정확도/실제 iPhone Safari 터치/200% 브라우저 확대는 검증 완료로 주장하지 않습니다.

OCR이 불확실하면 최대 한 번 기기 내부에서 확대·명암 보정한 사진(세로 사진은 하단 캡션 영역)을 재인식합니다.
더 나은 주소/후보를 얻었을 때만 두 번째 결과를 사용하며 유료 API를 호출하지 않습니다.
한영 병합은 인접 위치와 업종 단서를 함께 사용하며, 확정된 동일 장소라는 의미가 아닙니다.
원문은 사진 번호별로 표시하며 합쳐진 표기는 후보에 남겨 직접 비교할 수 있습니다.

남은 과제: 사용자 원본의 정확 인식 확인, 작은 상호/특이한 글꼴의 한글 인식, 지도 검색에 의한 동일 장소 확인.

## 후속 수정: 실제 화면에 보고된 누락 규칙

- 대소문자/숫자/기호가 섞인 `ofolZtojl=2]d` 형태도 낮은 신뢰로 표시합니다.
- 상호와 영문 사이에 주소/UI 줄이 끼어 있어도 제한된 범위에서 묶습니다.
  서로 다른 주소가 확인되는 두 장소는 합치지 않습니다.
- 주소 뒤 ©/®/™/아이콘을 제거하며 도로명 숫자·하이픈·동/층 표기는 유지합니다.
- `주소:` 라벨, 붙은 도시명, 두 줄 주소를 처리합니다.
- 로컬 재인식의 세로 사진 하단 범위를 좁혔으며, 전체 사진에서 찾은 후보를 줄이는 재인식 결과는 채택하지 않습니다.

단위 테스트는 주소/영문 순서를 바꾼 보고 문자열 및 혼합 대소문자 변종을 검사합니다.
브라우저 회귀 테스트는 보고된 문구를 입력해 후보3개, 정제 주소3개, 불확실성 경고,
확인 전 저장 없음까지 검사합니다. 사용자 원본 사진을 실제 OCR로 실행한 결과는 아닙니다.
따라서 첫 번째 사진 주소의 실제 재인식 성공과 세 번째 한글 상호의 정확 인식은 여전히 미검증/미해결입니다.
