# 여러 단서로 장소 찾기

## 현재 동작

사진 OCR과 로컬 저장 구조는 유지했습니다. 읽힌 상호/한영 별칭/지점/업종/지역/주소를 분리하고 검색 계획을 만듭니다.
앱은 한글을 읽지 못한 경우 한국어 브랜드를 만들어 넣거나 예시 DB로 정답을 대체하지 않습니다.
카페 단서는 CAFE/COFFEE/BAKERY 및 한글 업종 표현에서 추론하며 공식 분류로 검증한 결과와는 다릅니다.

예: `아이갓에브리씽 대역박점`, `CAFE I GOT EVERYTHING`, `서울 종로구 세종대로 193`

1. 아이갓에브리씽 서울 종로구 카페
2. CAFE I GOT EVERYTHING 서울 종로구 카페
3. 서울 종로구 세종대로 193 카페

한글 상호가 깨졌다면 첫 단계는 읽힌 영문을 사용합니다. 업종은 검색어·순위 단서이며 결과를 강제로 제외하는 API 필터가 아닙니다.
검색 결과는 상호/브랜드, 지점, 지역, 도로명과 건물번호, 업종으로 비교합니다.
같은 건물의 다른 카페는 확정하지 않습니다. 주소가 맞고 상호가 다른 경우에도 수동 확인이 필요합니다.
서울/서울특별시 등 일부 행정구역 표기 차이는 정규화합니다. 지점 약칭과 공식 지점명이 다르면 보수적으로 검토합니다.

후보당 최대3회 검색하고 명확한 결과가 나오면 중단합니다. EvidencePlaceResolver는 세션 캐시100개/5분과 동시 쿼리 병합을 사용합니다.
기존 OCR 파이프라인의 세션 캐시도 유지됩니다. 공급자의5분 TTL이 파이프라인 전체 TTL을 보장하는 것은 아닙니다.
사진당 최대5개 후보를 유지합니다. 앱에서 실제 검색을 설정한 경우 한 분석당 고유 후보5개까지만 자동 Resolver를 호출해 최대15개 검색 요청으로 제한합니다. 그 이후 후보도 삭제하지 않고 미확인 상태로 확인·저장할 수 있게 남기며 한도 안내를 표시합니다. 같은 검색어의 세션 캐시는 유지됩니다. 무료 쿼터/과금 조건은 카카오에서 확인해야 합니다.
AI fallback은 호출하지 않습니다.

## 키 없이 지금 사용

후보 카드에 업종/지역 단서, 접을 수 있는 검색 계획, 네이버지도/카카오맵 검색 버튼을 제공합니다.
버튼은 사용자가 누를 때 준비된 첫 검색어로 외부 지도를 열며, 검색 결과를 SpotClip이 자동으로 읽거나 확인하는 기능은 아닙니다.
확인 후 직접 저장한 OCR 후보는 계속 unverified입니다. 카페 단서는 개인 목록의 분류에도 사용합니다.

## 카카오 검색만 연결 (사진·OpenAI 전송 없음)

`api/search.mjs`는 기존 인증/CORS HTTP handler와 카카오 mapper를 재사용합니다.
기존 AI 분석의 카카오 검색도 `server/kakao.mjs`를 사용하므로 검색 구현을 복제하지 않았습니다.
요청은 `{query:string}`, 응답은 `{matches:ResolvedPlace[]}`입니다. 이미지는 받거나 전송하지 않습니다.

다음은 사용자가 준비해야 합니다.

1. Kakao Developers 앱/Local API 이용 조건·쿼터를 확인하고 REST API 키를 발급합니다.
2. `iphone-test` 소스 브랜치를 서버리스 호스트에 배포하고 `/api/search` HTTPS 주소를 준비합니다.
   Vercel에서는 Framework Preset Other, Build Command `mkdir -p public`, Output Directory `public`로 설정하면
   Expo 네이티브 빌드를 서버 배포 단계에서 실행하지 않고 `api/` Node 함수를 배포할 수 있습니다.
   호스트의 현재 Node 함수 설정·요금/런타임 제한은 배포 시 확인하세요. 이 작업에서는 원격 서버를 배포하지 않았습니다.
3. 서버 환경에 KAKAO_REST_API_KEY, 무작위32자 이상 SPOTCLIP_ACCESS_TOKEN,
   SPOTCLIP_ALLOWED_ORIGINS=https://ddi04078.github.io 를 설정합니다.
   로컬 웹 origin도 사용하면 쉼표로 추가합니다. 경로 `/spotclip/`은 origin에 넣지 않습니다.
   **OpenAI 키는 설정할 필요가 없습니다.** 기존 /api/analyze는 키 미설정 상태로 둡니다.
4. 앱 설정 → ‘카카오 장소 검색만 연결’에서 서버 주소와 별도 접근 토큰을 입력합니다.
   카카오 REST 키를 앱/채팅에 입력하지 마세요. 상호·주소 외부 전송에 동의한 뒤 연결 버튼을 누릅니다.
5. 첫 분석에서 실제 응답을 확인합니다. 설정 성공 표시는 연결/키 유효성 검증 완료가 아닙니다.
   토큰·동의는 메모리만 사용하며 새로고침하면 해제됩니다. 저장된 장소는 유지됩니다.

로컬 서버는 `.env` 설정 후 `npm run server`로 실행합니다. `/health`는 프로세스 확인일 뿐 API 키 유효성 검사가 아닙니다.
현재 인증·동시성 제한은 개인 테스트용이며, 공개 서비스에는 사용자 인증·지속적인 전체 rate limit을 추가해야 합니다.

## 검증과 미검증

- Mock HTTP 응답으로 쿼리 순서/최대3회/조기 종료/캐시/상호 오타/주소·업종 충돌/동일 건물 모호성/지점 구분 검사
- 기존 공통 OCR pipeline에 resolver 주입 → 공식 목록 결과 표시 → 사용자 저장 검사
- 웹 설정 전송 동의/검색어만 전송/토큰 새로고침 삭제/지도 버튼 검색어 검사
- 기존 Mock·저장·중복 방지·스크롤 테스트 유지
- 실제 카카오 키 없음: 라이브 검색 결과·호출 성공·정확도는 미검증
- 카카오 최신 문서 URL은 현재 환경에서403으로 차단되어 재확인하지 못함:
  https://developers.kakao.com/docs/latest/ko/local/dev-guide
- 사용자 원본 이미지 및 실제 iPhone 검증은 별도 필요. 이번 변경으로 한글 OCR 자체가 완벽해진 것은 아님
